# Research Develop 스킬

연구자의 초기 아이디어를 명확한 연구 설계로 발전시키는 Claude Code 스킬.

## 이 스킬이 하는 일

연구자가 "이런 주제로 이런 연구를 해볼까 싶은데"처럼 막연한 아이디어를 공유할 때, Claude가 단순 응원자가 아닌 **비판적 협업자**로 작동하도록 지침을 제공한다.

### 주요 동작

- **무비판적 칭찬 금지**: "좋은 아이디어네요"로 시작하지 않는다
- **진짜 질문 추출**: 연구자의 부연 설명·구체적 장면·반복되는 불만에서 핵심 질문을 포착
- **범위 초점화**: 기본 편향을 "빼기"로 설정. 연구자가 과잉 설계하지 않도록 경계
- **과잉 설계 방지**: 방법론 제안 전에 현실 조건 먼저 확인
- **폐기 이력 보존**: 같은 대화에서 이미 폐기된 안을 재제안하지 않음
- **언어 신호 감지**: "굳이", "일단은", "근데 이렇게 되면" 같은 신호 해석

## 파일 구조

```
research-develop/
├── SKILL.md                         # 메인 스킬 파일
└── references/
    ├── language_signals.md          # 언어 신호 해석 상세
    ├── research_types.md            # 연구 유형별 체크리스트
    ├── common_traps.md              # 흔한 함정과 대응
    ├── dialog_examples.md           # 실제 대화 예시
    ├── research_scale.md            # 박사/석사/학술지/학부 규모별 조정
    └── quantitative_research.md     # 양적 연구 (설문·패널·변인 관계) 가이드
```

## 설치 방법

### Claude Code에 설치

1. 이 폴더를 Claude Code의 스킬 디렉토리에 복사
   - 공식 스킬 디렉토리 위치는 Claude Code 문서 확인
   - 일반적으로 `~/.claude/skills/` 아래

```bash
cp -r research-develop ~/.claude/skills/
```

2. Claude Code에서 스킬이 인식되는지 확인
   - 사용자가 연구 주제를 언급하면 자동으로 호출됨

### 프로젝트별 스킬로 사용

특정 박사논문 프로젝트에만 사용하려면, 프로젝트 루트에 `skills/` 디렉토리를 만들고 그 안에 넣는다.

```bash
mkdir -p your_dissertation/skills
cp -r research-develop your_dissertation/skills/
```

그리고 Claude Code 설정에서 해당 경로를 스킬 경로로 추가한다.

## 사용 방법

### 자동 호출

스킬의 `description`에 맞는 상황이 감지되면 Claude가 자동으로 활성화한다. 다음과 같은 입력이 트리거가 된다.

- "박사논문 주제로 이런 걸 생각 중이야"
- "연구 문제를 어떻게 좁혀야 할지 모르겠어"
- "이 주제로 논문 쓸 수 있을까?"
- "학술지에 투고할 연구를 디자인하려고 해"

### 명시적 호출

자동 호출이 되지 않으면 명시적으로 요청할 수 있다.

> "research-develop 스킬을 사용해서 내 박사논문 주제를 디벨롭 도와줘."

## 작동 방식

### 대화 시작 시
Claude는 먼저 연구 유형(경험 해석/설계·개발/실증·실험/비판·담론/이론 구성)과 연구 단계(주제 탐색/문제 확정/방법론 설계 등)를 파악한다. 불명확하면 가장 중요한 한 가지만 먼저 묻는다.

### 대화 중
매 턴마다 암묵적으로 다음 상태를 추적한다.

- 연구 유형이 확정되었는가?
- 핵심 질문이 추출되었는가?
- 범위가 적절한가?
- 방법론이 질문에 맞는가?
- 실행 가능성이 확인되었는가?
- 연구자의 위치성이 명확한가?

미확정 상태를 우선적으로 다룬다. 단, 한 턴에 모든 항목을 다루지 않는다.

### 대화 종료 시
연구자가 "정리해줘"를 요청하면 다음을 제공한다.

1. 확정된 사항
2. 보류 중인 사항
3. 폐기된 안과 그 이유
4. 다음 턴에 다룰 가장 중요한 질문

## 이 스킬을 만든 맥락

이 스킬은 실제 박사논문 디벨롭 대화에서 반복적으로 관찰된 패턴을 추출하여 만들어졌다. 핵심 관찰은 다음과 같다.

- 연구자의 진짜 관심은 종종 **부연 설명**에 숨어 있다
- 연구자는 기본적으로 **과잉**으로 시작한다. 스킬의 역할은 **빼는 것**이다
- AI의 과잉 설계는 연구자의 현실 감각에 막혔을 때 **즉시 철회**되어야 한다
- 폐기된 안을 기억하지 못하면 같은 결정을 반복하게 된다
- "좋은 아이디어네요"는 해로운 응답이다

## 기여와 개선

이 스킬을 개선하려면 `references/` 아래 파일들을 수정한다.

- 새로운 언어 신호가 발견되면 `language_signals.md`에 추가
- 새로운 연구 유형이 필요하면 `research_types.md`에 추가
- 새로운 함정 패턴을 발견하면 `common_traps.md`에 추가
- 좋은/나쁜 응답 예시를 발견하면 `dialog_examples.md`에 추가

주 `SKILL.md`의 철학과 원칙은 가급적 그대로 유지한다. 참조 파일들이 살을 채우는 역할이다.

## 한계

- **학위 규정에 대해서는 항상 확인 요청**: 스킬은 학위 규정·심사 관행·투고 학술지 규정을 모르므로 단정적으로 말하지 않는다. 연구자에게 확인을 요청한다.
- **학문 분야별 차이 존재**: 주로 교육학·사회과학 맥락에서 설계되었다. 자연과학·인문학 분야는 보완이 필요할 수 있다.
- **다국어 대응 부재**: 지금은 한국어 언어 신호만 다룬다. 영어권 연구자와의 대화라면 `language_signals.md`를 확장해야 한다.
- **통계 기법의 세부 절차**: `quantitative_research.md`는 양적 연구 디벨롭의 일반 원칙을 다룬다. 특정 통계 기법(SEM 세부 모수 추정, 특정 소프트웨어 명령 등)의 구체적 수행은 다루지 않는다. 이는 별도 통계 컨설팅 영역.
